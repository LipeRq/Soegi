## 3. 会社サイト（withsoegi.jp）の変更

### 用語の変更（重要：claude.ai 側の資料と名前をそろえてください）
3つの頼み方の名前を、人が普通に使う言い方に変えました。旧名称は、サイトから完全になくなっています。

| 旧名称 | 新名称 | 中身 |
|---|---|---|
| 仕組みをつくって、卒業する | **業務の仕組みづくり** | お試し導入5万円→月5万円。終えるときに手順書をお渡しする |
| 使い続けて、育てる | **月額のAIサービス** | ナレッジ検索・宿の多言語対応・チャットボット |
| 必要なものだけ、頼む | **単発のご依頼** | 見える化・小さなツール・研修・ホームページ制作 |

- 「卒業」は「引き渡し」「終える」に、「育てる」は使わない形にした。「添え木」の話は、事業者概要の「ソエギという名前について」にだけ残している。
- トップの大見出し「変わる時代に、ITで寄り添い続けます」は、そのまま。キャッチコピー「削減できた時間を、数字で確かめてから続ける。」も、そのまま（変えるかは未決。下の「決めてほしいこと」）。
- そのほか、見出しを自然な言い方に直した（「ご依頼は、3種類です」「進め方は、最初に決めています」「AIの答えの作り方」「ほかの方法との比較」など）。

### 進め方の変更（重要）
- お客さまに負担の重い作業（作業時間の記録・計測シートの記入）を、**サイトから完全に外した**。
- 「お試し導入」の流れは、トップでは3つ：無料相談（60分）→ お試し導入（1ヶ月）→ 続けるか、決める。
- `/graduate/` では5つ：無料相談 → お試し導入 → 結果を見て、決める → 続ける → 引き渡し。
- 「測って比べる」の表現（導入前後を数字で並べる、「比べる表」の見本の節）は、目立つ所から外した。「結果を見て、決める」に統一。キャッチコピーと、料金ページの「元が取れるかの目安」の計算、月額サービスの「質問の件数などの数字で判断」は、そのまま残している。
- サイトのチャットボットの案内文（進め方の説明）も、同じ4つの手順にそろえた。

### 代表者・事業者概要
- 代表者：山形のIT企業でシステムエンジニア、その後、東京のIT企業でITコンサルタント。子どものころからパソコンに触れ、機械が好きで、パソコンを自作したりソフトウェアをつくったりするのは、いまも変わらない、と記載。
- トップの代表者欄：名前と短い紹介だけ（実績カードは外した）。
- `/about/` の構成：代表者 → これまでの仕事（縦の年表）→ ソエギを始めた理由 → ソエギの強み／大事にしていること → 「ソエギ」という名前について（添え木の話）→ 事業者概要の表。実績の4枚のカード（2,000万人規模、導入5社・運用9社、生成AI、C#・SQL）は削除した。
- 「ご紹介くださる方へ」のブロックは削除した。

### 「安心のために」
- 見出し「AIに社内の書類を預けるということ」。「絶対に漏れない」とは言わず、**入力の最小化／環境の限定／保管と削除の管理**の3点を運用の基準として記載（学習に使われない設定または法人向けプランのツールだけを使う、事業専用の端末とアカウント、AIの出力は人が検証、作業終了後に削除して報告、希望があれば相談段階から秘密保持契約）。

### 読みやすさ・スマホ表示
- 文字を減らした（トップの各節、詳細ページの前置き、デモの注記）。お試しの範囲（どこまでやるか）は、通常は閉じておき、押すと開く形。
- 本文を、読点・句点のまとまりごとに折り返すようにした（iPhone の Safari は文節での折り返しに未対応のため、まとまりを崩さない指定を併用）。見出しの行の長さもそろえた。
- スマホの基本の文字を小さくし、行間を調整。お知らせ欄は、1件ずつ区切り線を入れ、日付とラベルの下に本文を置く形に。
- ヘッダーのロゴが1100〜1240px幅で縦に折れる不具合、料金ページの見出しの二重表示、見出し下の余白、事業者概要の余白を修正。
- お知らせ欄の内容は、元の3件のまま（今回の更新は載せないことにした）。

### 既知の課題
- 右下の赤い「質問する」ボタン（チャット部品）が、スマホで本文やボタンに重なって見えることがある。直すには、デモ側のチャット部品（`public/widget/chat.js`）を、スマホでは小さい丸ボタンにする対応が必要（未着手）。
- iPhone の Safari 実機での最終確認は、事業者側の目視による（こちらの環境では Safari を動かせない）。

## 4. デモ（demo.withsoegi.jp）の変更

- **入口を一覧に作り直した**：動く見本のタイルと、丸いボタン8つを外し、「デモ名・一文・ボタン」の一覧に。分類は、次の4つ。
  - 入力と集計の手間を減らす（レシートを読み取って、Excelにまとめる／打刻データから、残業時間を集計する／売上の表から、月次の報告書をつくる）
  - 社内の資料に答えさせる（社内ナレッジ検索）
  - 外国語の問い合わせに答える（外国人スタッフ向けの案内／宿の多言語対応／サイトのチャットボット）
  - ホームページの見本（5種類）
- **各デモ画面**：「御社の場合（試算）」の計算表を、全画面から外した（試算は、サイトの料金ページの計算に一本化）。見出しと説明を、入口と同じ平易な名前と一文にした。注意書きは「架空のデータです。入力内容は保存しません。…」の形にそろえた。
- レシート：形式の選択（標準・仕訳・弥生・freee）は、「形式を選ぶ」ボタンの中にしまった。説明文を短縮。
- 残業の集計：「打刻の集計／シフト表のチェック」の切り替えを外した。
- 社内ナレッジ検索：20件ある過去の見積書は、最初は閉じておく（根拠に出たときは自動で開く）。質問のカードの「管理画面を開く」を外した。
- 宿の多言語対応：同じ黄色の「下書きです」が2回出ていたのを1回に。
- サイトのチャットボット：見本のウェブサイトの飾り（灰色のバー、ブラウザの窓の点）を外した。
- 入口に出していない控えの画面（注文書→受注データ、シフト表のチェック、音声日報→報告書）は、URLだけで開ける。これらの画面の中の文言は、まだ見直していない。

## 6. 事業者側で決めてほしいこと・確認してほしいこと

1. **キャッチコピー**：「削減できた時間を、数字で確かめてから続ける。」を変えるか。「測って比べる」の表現を外したので、このコピーだけが浮いて見える可能性がある。案：「小さく試して、合えば続ける。」「1ヶ月で効果を確かめてから、続ける。」

   - 山形のIT企業でシステムエンジニア、その後、東京のIT企業でITコンサルタント
   - 会員数2,000万人規模の顧客基盤をもつ企業の案件／CRM・SFAの導入5社・運用支援9社ほど（※カードは外したが、文章に一部残っている）

4. **お客さまに記録を頼まない運用**：サイトでは「お客さまに記録をお願いすることはありません」と約束している。実際にどう効果を把握するか（お試し中の聞き取りなど）が、運用で守れる形か。
