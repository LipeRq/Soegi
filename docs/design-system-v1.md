# ソエギ デザインシステム v1「ライブ」（デモで実装した内容と、本番への適用）

作成：2026年10月11日。対象は `design/live-ui` ブランチの作業ツリー（入口＋デモ5画面）。**コミットも公開もまだ**で、画面ごとのレビューと全体確認も終わっていない（10章）。
書いてあることは、すべて実際のコード（`public/css/style.css`、`public/js/motion.js`、各画面の CSS/JS）から確かめたもの。確かめられなかったことは10章に分けて書いた。
読む人：①オーナー（デザイナーではない）②本番の画面を作る人（人でも AI でもよい）。②は2章・3章・4章・6章・7章だけ読めば作業できるようにした。

## 1. 目的と考え方

### 1-1. なぜ変えたか

| 前の画面 | 困りごと |
|---|---|
| どの箱も同じ白い枠で、同じ重さ | 何を見ればよいかが分からない。読みにくい |
| ほとんど動かない | 「AIが仕事をしている」ことが伝わらない。ふつうの業務ソフトに見える |
| 汎用の部品をそのまま並べた見た目 | 「AIが作った感じ」がして、ソエギらしさがない |

選んだ方向が「ライブ」：白い角丸のタイルを、青みのある灰緑の地に置く。見出しは Zen Maru Gothic、本文は BIZ UDPGothic、数字は IBM Plex Mono。強調の色は朱ひとつ。動きは**しっかり動かす**が、必ず「いま何をしているか」を見せるために使う。

### 1-2. 3つの原則

| # | 原則 | 具体的には |
|---|---|---|
| ① | **重さに差をつける** | 1つの段に主役は1つ。白いタイルは主役とまとまった結果だけ。設定・補足・注意書きは地の上に置く。全部を同じ箱にしない |
| ② | **動きは仕事の証拠** | 動くのは、実際に起きたことの見せ方だけ。数字は本当の値を数え上げる。待ち時間を作らない。飾りの動きは足さない |
| ③ | **安全表示は動きより強く、先に** | 「要確認」「注意」「下書きです」「AIの翻訳です」「見当たりません」は、動かさず、はじめから全文を出し、それが守る内容より後に出さない |

### 1-3. やってはいけないこと

| してはいけない | 理由 |
|---|---|
| 結果を出すまでに、見せるためだけの待ち時間を入れる | 動きの正直さ（4-2）。実測の秒数が嘘になる |
| 進み具合を作り物にする（実際の処理と無関係に伸びる棒） | 同上 |
| 測った数字（かかった秒数など）を動きで変える | 同上。数え上げるのは「手計算なら」などの計算値と件数だけ |
| 注意書き・要確認を、タイピング・フェード・折りたたみの後ろに隠す | 原則③ |
| 色だけで状態を伝える | 色が見分けにくい人がいる。必ず言葉も出す（6-3） |
| 新しい色・書体・影を、画面の CSS に直接書く | 2章のトークンだけ使う。足りなければ共通ファイルに足す（7-4） |
| 動きを減らす設定の人に、動きを強いる／内容が見えなくなる | 4-3 |
| 主役を2つ作る（朱のボタンを1画面に複数、大きなタイルを横並びで全部強調、など） | 原則① |

### 2-3. 書体

| 変数 | 並び | 役割 |
|---|---|---|
| `--display` | "Zen Maru Gothic", "BIZ UDPGothic", "Hiragino Maru Gothic ProN", "Yu Gothic", Meiryo, sans-serif | 見出し（h1〜h3）、ボタンの大きな文字、札の文字 |
| `--sans` | "BIZ UDPGothic", "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif | 本文（UD書体。年配の方・外国人スタッフにも読みやすい） |
| `--mono` | "IBM Plex Mono", ui-monospace, "Cascadia Mono", Consolas, monospace | 数字（件数・金額・時間）、番号の丸、アドレス |

読み込みは各ページ共通の1行（これと違う行を使わない）：

```
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=BIZ+UDPGothic:wght@400;700&family=IBM+Plex+Mono:wght@400;500&family=Zen+Maru+Gothic:wght@500;700&display=swap">
```

| 要素 | 大きさ・太さ |
|---|---|
| 本文 | 16px／行間 1.75 |
| `h1` | `clamp(23px, 3.6vw, 34px)`、Zen Maru 700、行間 1.4。入口の見出しだけ `clamp(27px, 5.2vw, 46px)` |
| `h2` / `h3` | 19px / 16px（画面側で `clamp(19px, 2.4vw, 22px)` などに上げてよい） |
| 大きな数字 `.stat b` | Plex Mono 500、32px。主役の数字は 38〜44px（経理の「かかった時間」「手入力なら」） |
| ボタン | 16px 太字。大きな操作ボタン（`#go` `#export` `#calc`）は 17〜19px |
| 表・入力・お知らせ | 14px（入力はスマホで 16px にして拡大表示を避けてよい） |
| 補足 `.small-note` | 13px |
| バッジ・凡例 | 12〜13px |
| `.reason`・サムネイルの名前 | 11px |

決まり：**読ませる文（指示・警告・答え）は 14px 以上。11〜13px は補足だけ**。数字には必ず `font-variant-numeric: tabular-nums`（`.stat b` などに設定済み）。見出しは `word-break: auto-phrase` で文節ごとに折る（未対応ブラウザは通常の折り返し）。

## 3. 部品（コンポーネント）

共通の部品は `style.css`、画面だけの部品は `css/<画面>.css`。「使う場面」の外では使わない。

### 3-1. 面（タイル・カード）

| 部品 | 使う場面 | 決まり | クラス |
|---|---|---|---|
| 白いタイル | 主役、まとまった結果、入口の見本 | 多くしすぎない（労務は4枚）。角丸 `--r-tile`、影 `--shadow`。**設定・補足・注意書きは乗せず、地に直接置く** | `section.card`、入口は `.tile` |
| 墨の面 | 結果の要約、お客さまの原文、次にすること | 白文字。緑は `--leaf-on-ink` | `.roi .res`、`.gate`、`.quad .origin`、`.ideas` |
| 輪郭だけの面 | 脇役（人数・行数、このデモで数えた分） | 背景なし、`--line` の枠 | `#stats .stat.quiet`、`section.card.session` |
| 点線の面 | まだ選ばれていない場所（入れ口、根拠） | 選ぶと実線や白い面に変わる | `.drop`、`.kb .evidence`、`.msg.bot.none` |
| 見本の窓 | 見本のサイトを見せる | 小さなブラウザの窓。文字の無い部品は静止（読み込み中に見せない） | `.mocksite`、`.page[data-profile]` |

### 3-2. ボタン・入力

| 部品 | 使う場面 | 決まり | クラス |
|---|---|---|---|
| ボタン | 操作 | 高さ 48px 以上、枠 1.5px の墨、`--r`。押すと 0.97 倍 | `button`、`.btn` |
| 主ボタン | その段で次にすること | **1画面に1つ**。朱の面、白文字。押せるようになったら輪を出して知らせてよい（`ring`） | `button.primary` |
| 大きな操作 | 画面の山場（読み取る、Excel、計算する） | 高さ 56〜60px。画面側の CSS で大きくする | `#go`、`#export`、`#calc` |
| 小さなボタン | 表の中の「削除」など | 44px（共通で揃えてある） | `button.small` |
| リンク風ボタン | 目立たせたくない操作 | 朱の下線 | `button.link` |
| 入力欄 | 文字・数字・選択 | 高さ 44px 以上、枠 1.5px `--field`、フォーカスで墨の枠＋輪。ラベルは上に 14px | `input`、`select`、`textarea`、`label` |
| 選択式の札 | 3択など（様式、業種、言語） | 選んだものは**面＋枠＋言葉（選択中・表示中）**。`aria-pressed` か `aria-selected` を必ず付ける | `.opt`（経理）、`.profiles`（見本）、`.faq-lang`、`.examples button`（宿）、`.roles button`（ナレッジ） |

### 3-3. 手順・数字・お知らせ

| 部品 | 使う場面 | 決まり | クラス |
|---|---|---|---|
| 3段階の帯 | 経理・労務の「撮る → 確かめる → Excelに」 | 画面の上に貼り付く（`position: sticky`）。いまの段は墨の丸＋朱の番号、終わった段は緑。切り替えは `setStep()`（common.js） | `.steps`、`li[aria-current=step]`、`li.done` |
| 大きな数字 | 結果の要点 | 数字は Plex Mono。色は意味に合わせる。数え上げる値は終わりの文字を元の表示と同じにする | `.stats`、`.stat`、`.stat.good`／`.warn`／`.danger` |
| お知らせ | 注意・補足 | 左の丸＋面の色で3種。**必ず内容より前に置く**。動かさない | `.notice`（朱＝必ず読む）、`.notice.plain`（墨＝補足）、`.notice.warn`（黄＝注意） |
| 強いお知らせ | 「下書きです」など、画面でいちばん強い注意 | 黄の枠＋「!」の印＋大きな字 | `.notice.draft`（宿） |
| エラー | 入力や通信の失敗 | 朱の太字、`role="alert"` | `.err` |

### 3-4. 表・札・凡例

| 部品 | 使う場面 | 決まり | クラス |
|---|---|---|---|
| 表 | 一覧・編集 | 横に長い表は `.tablewrap` の中で横に送る。縦線はなくして、入力欄は下線だけにしてよい（色の付いたマスを先に見せるため） | `.tablewrap`、`table` |
| スマホの表 | 760px以下 | 1件ずつのカードに組み直す（見出し行は消し、各マスに `data-label` を出す）。重要な項目（番号・写真・確かめる点）を先に並べ替えてよい | `table.stack`、`td.nolabel` |
| 色の付いたマス | 要確認・注意 | **色＋言葉**（マスの中に「要確認」「注意」を出す） | `td.red`、`td.yellow`、`.flag.red/.yellow`、`.reason` |
| バッジ | 状態の印 | 12px 太字、必ず言葉を含める | `.badge` ＋ `.red/.orange/.yellow/.streak/.ok/.gray` |
| 凡例 | 色の意味 | 色の四角＋言葉 | `.legend` |
| 小さな札 | 入口の見本 | 弾んで出る | `.chip`（`.r/.y/.o/.w`）、`.cite` |

### 3-5. 切り替え・会話・根拠・グラフ

| 部品 | 使う場面 | 決まり | クラス |

## 4. 動きの決まり

### 4-1. 動きの語彙

CSS の部品は `style.css`、JS の部品は `public/js/motion.js`。両方とも「動きを減らす」設定では動かない（4-3）。

| 名前 | 種類 | 使う場面 | 長さ |
|---|---|---|---|
| `rise` | CSS（keyframes） | 下から出る。ページの見出し・タイル・数字・吹き出しの出現（`main > h1` `section.card` `.stat` `.msg` は既定で付く） | `--t-slow`／吹き出しは `--t` |
| `pop` | CSS | 小さなものが弾んで出る（札、サムネイル、チェック、ダイアログ） | `--t` |
| `grow` ＋ `.play` | CSS | 棒が左から伸びる。`replay(el,'play')` でもう一度。`--i` で遅らせる（1つ 70ms） | .9s |
| `.stagger` ＋ `--i` | CSS＋JS | 並んだものを順に出す。JS の `stagger(親, 最大)` が `--i` を入れる。**最大 12 個目から先は一緒に出す** | 1つあたり 55ms 遅れ |
| `flash` | CSS＋JS | 値が変わった所が一瞬光る。JS は `flash(el)` | 1.2s |
| `shake` | CSS＋JS | 入力の間違いを横に揺らす。`shake(el)` | .4s |
| `ring` | CSS | ボタンや印のまわりに輪が広がり「ここ」と知らせる。**回数を決める**（2〜3回）。無限に回さない | 1.6s（無限なのは `.steps` の現在の段と入口の `.ringing` だけ） |
| `.reveal` | CSS | スクロールで出る（`animation-timeline: view()`）。**対応しないブラウザは、はじめから見えている** | スクロールに連動 |
| `.thinking`／`thinking(label)` | CSS＋JS | 「考え中」の3つの点。`role="status"` と `aria-label` 付き。**本当に待っている間だけ**出す | 1.1s の繰り返し |
| `.scanning` | CSS | 読み取り中の写真・資料一覧の上を走る線（`.scanning` を付けている間だけ） | 1.4s の往復 |
| `shimmer` | CSS | 結果が入る場所の「行の形の影」。待っている間だけ | 1.4s の繰り返し |
| `.typing`／`typeText(el,text,{cps,maxMs,signal})` | CSS＋JS | AIの答えを1文字ずつ出す。**必ず最後に全文が入る**。`maxMs` は既定 2.4s、`signal` で途中終了 | 上限 2.4s（画面ごとに 0.8〜2s） |
| `countUp(el,to,{from,duration,format})` | JS | 数字を数え上げる。終わりの表示は `format(to)` と**必ず同じ**。動きを減らす設定・数でない値は即座に終わりの値 | 既定 900ms（変更時は 450ms） |
| `replay(el,cls)` | JS | クラスを付け直して CSS の動きをもう一度流す | — |
| `onVisible(el,fn)` | JS | 画面に入ったとき1回だけ実行（棒や数字を、見えてから動かす） | — |
| `watchVisible(el)` | JS | 画面に見えている間だけ true。**繰り返しの動きを、画面の外・裏のタブで止める** | — |
| `spotlight(selector)` | JS | マウスの位置にタイルの光が付いてくる（入口のタイル）。タッチ端末・動きを減らす設定では何もしない | — |
| `reduced()`／`sleep(ms)` | JS | 動きを減らす設定かどうか／待つ | — |
| 画面をまたぐ動き | CSS | 4-4 | .26s |

画面専用の動き（共通にしていないもの）：`roll`（入口の見出しの入れ替え）、`sweep`／`kb-sweep`（引用文に蛍光ペンが左から走る）、`page-in`／`page-out`（チャットボットの見本ページの入れ替え）、`settle`（宿の結果の位置だけの出現）。

### 4-2. 動きの正直さ（守る決まり）

| # | 決まり | 理由 |
|---|---|---|
| ① | 実際の処理に、見せるための遅れを足さない | 「動きがあるから遅い」を作らない |
| ② | 進み具合の棒は、実際に終わった件数から作る | 作り物の進みを見せない |
| ③ | 測った数字（かかった秒数）は変えない。出すときも実測値そのまま。待っている間の経過秒は、同じ開始時刻からの実測 | 数字の信頼 |
| ④ | 数え上げてよいのは、すでに決まっている値（件数・計算値）だけ。**終わりの表示は動きなしの表示と同じ文字** | 嘘をつかない |
| ⑤ | **安全表示（要確認・注意・下書きです・AIの翻訳です・見当たりません・必ずリーダーに確認）は、動かさず、はじめから全文を出し、内容と同時かそれより前に出す。タイピングの対象にしない** | 原則③ |
| ⑥ | 数が変わる安全表示（要確認・注意の件数）は、数え上げず即座に更新して光らせるだけにする | 遅らせない |
| ⑦ | タイピングは2.5秒以内に必ず全文が入る。タップ・次の操作で即座に全文。全文は先に DOM に入れて見えなくしておき、画面の読み上げは1回だけ | 待たせない・読み上げを邪魔しない |
| ⑧ | 動いている間も入力は止めない。操作を受け付けないオーバーレイを使わない | 使いやすさ |
| ⑨ | 動きは「結果が出たあと」の見せ方か、「待っている間」の状態表示のどちらか。待っている状態は本当に待っている間だけ（`finally` で必ず外す） | 状態の取り残しを防ぐ |
| ⑩ | 飾りだけの動きは、画面に入ったとき1回まで。繰り返してよいのは、待っている印（考え中・読み取り線）と、入口の見本（見えている間だけ） | 4-5 |

### 4-3. 「動きを減らす」設定

`@media (prefers-reduced-motion: reduce)`（style.css）：すべての `transition`・`animation` を止め、`scroll-behavior` を `auto` にし、画面をまたぐ動きも止める。JS 側は `reduced()`。

| 部品 | 動きを減らす設定のとき |
|---|---|
| `countUp` | すぐ終わりの値 |
| `typeText` | すぐ全文 |
| `thinking`／`.scanning`／`shimmer` | 点・線は止まって見えるだけ（`.scanning` は JS が付けない画面もある）。待っていることは「していること」の文でも分かるようにしておく |
| `stagger`／`rise`／`pop` | 動きなしで最初から見える |
| スクロール | `behavior: 'auto'`（即座） |
| 入口の見本（`startLive`）と見出しの入れ替え | 動かさない。見出しは「探す・答える・訳す」を3つ並べて見せる |

**確かめ方**：OS またはブラウザで「動きを減らす」を入れ、全画面を最後まで通す。すべての内容が見え、操作できること。新しい動きを足すときは、この設定で内容が隠れたままにならないか（`opacity:0` で始まる動きに注意）を必ず見る。

### 4-4. ページをまたぐ動き（View Transitions）

`@view-transition { navigation: auto; }` と、`.vt-receipt` `.vt-attendance` `.vt-knowledge` `.vt-inn` `.vt-chatbot`（`view-transition-name`）、`.brand`。入口のタイルの見出し（`<h3 class="vt-…">`）が、開いた画面の `<h1 class="vt-…">` へつながって動く。

| 項目 | 内容 |
|---|---|
| 作り方 | 入口のタイルの見出しと、移動先の `<h1>` に**同じ**クラスを付ける。`<h1>` にクラスを付け忘れると、つながらないだけで壊れない |
| 対応 | 同じオリジン（`demo.withsoegi.jp` の中）の移動だけ。**`withsoegi.jp` ⇔ `demo.withsoegi.jp` の移動では動かない**（オリジンが違う）。対応ブラウザは Chromium 系と新しい Safari（版は10章で未確認） |
| 未対応のとき | ふつうのページ移動になるだけ。内容も操作も同じ |
| 動きを減らす設定 | 止まる（4-3） |

### 4-5. 負荷（重くしない）

| 決まり | 具体的には |
|---|---|
| 繰り返しの JS は見えている間だけ | 入口の `loop()` は `watchVisible()` が false の間は待つ（画面の外・裏のタブ） |
| 繰り返しの CSS は待っている間だけ | `.thinking` `.scanning` `shimmer` は状態クラスを外すと止まる。状態に関係なく回るのは、`.steps` の現在の段の輪、入口の見出しの `roll` と `.ringing`、読み取り中の進み具合の棒の `shimmer`（棒が表示されている間）。いずれも小さい（端末の負荷は10章で未確認） |
| 一度きりの動きは `transform` と `opacity` を中心に | 棒は `transform: scaleX`。レイアウトが動く値（幅・高さ）を動かさない。例外：進み具合の棒の `width`（ここは本当の進みを見せる） |
| 長い一覧は遅れを打ち切る | `stagger` の既定は12個まで。それ以降は一緒に出す |
| 数え上げは `requestAnimationFrame` | 同時に何本も回さない。複数の数字は同じ長さに揃える |
| タイプの上限 | `maxMs`（0.8〜2s）を必ず付ける |
| 書体は3つだけ | 追加しない（読み込みが増える） |

## 6. 守る決まり

### 6-1. セキュリティ（CSP：`public/_headers`）

`default-src 'self'; script-src 'self' https://challenges.cloudflare.com; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' blob: data:; connect-src 'self'; frame-src https://challenges.cloudflare.com; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`

| 決まり | 具体的には |
|---|---|
| `style=""` を書かない | 動的な値は `el.style.setProperty('--x', v)`（CSSOM）。`h()` の `style` オブジェクトも CSSOM 経由。棒の長さ、遅れ（`--i`）、色分けの割合はこの方法 |
| インラインの `<script>`・`onclick=""` を書かない | イベントは `addEventListener`／`h()` の `onclick` |
| スタイルシートは自分のものと Google Fonts だけ | 書体を自分のサーバーに置くなら CSP を直す（7-2） |
| テキストは `textContent`（`h()`） | `innerHTML` と `insertAdjacentHTML` は使わない。AIの出力は信用しない |
| 画像は `self`・`blob:`・`data:` | 外部の画像は使えない |

### 6-2. 変えてはいけないもの

動作、API の呼び出し、計算、出力する Excel の中身、要素の `id`、既存の日本語の文言。純粋な計算の部品（`overtime.js` `csv.js` `receipt-check.js` `*-xlsx.js` `xlsx-common.js` `roi.js` `pricing.js` `faq-html.js` `image.js`）は見た目の変更で触らない。`public/widget/chat.js` はサイトに埋め込まれている（7-3）。

### 6-3. アクセシビリティ

| 項目 | 基準 |
|---|---|
| 文字のコントラスト | 4.5:1 以上（2-2。新しい組み合わせは必ず計算する） |
| 押す所 | 44px 以上（`button.small`、`.roi .seg button`、`.stat input`、`.brand` などは共通ファイルで揃えてある） |
| キーボード | すべて操作でき、フォーカスが見える（`:focus-visible` は 3px の墨の輪）。`hidden` にして押せなくしない（経理のファイル入力は見えなくするだけ） |
| 状態は色＋言葉 | 要確認／注意／選択中／表示中／済／待ち／読めず／橙 80時間以上 |
| 読み上げ | `aria-live` を残す。動きだけの飾りは `aria-hidden="true"`。タイプ中の文は全文を先に DOM に置き、重ねたほうを `aria-hidden` にする |
| 動きを減らす | 4-3 |
| 言語 | 外国語の文には `lang`（ナレッジ・宿で付与済み）。**ベトナム語のアクセントの一部（ẫ など）は BIZ UDPGothic に無く、記号が離れて見える**。共通の書体トークン `--latin`・`--zh`・`--ko` と `:lang()` で当ててある。**実際の見え方は未確認**（10章） |

### 6-4. レスポンシブ

| 幅 | 決まり |
|---|---|
| 390px | **横スクロールを出さない**。広い表は `.tablewrap` の中で横に送るか、`table.stack` のカードにする。ボタンは全幅にしてよい |
| 760px以下 | 「スマホ」。表はカード、タブは切り替え式、横棒の数字は棒の下 |
| 800px前後 | 3列は2+1に割れやすい。割れる幅では1列にする（宿の例など） |
| 1280px | 本文は最大 1180px。広い画面では要確認を右に立てるなど、読む順を保ったまま並べ替える |
| 貼り付き | `.steps`（高さ約70px）の下にフォーカスが隠れないよう `scroll-padding-top`・`scroll-margin-top` を付ける |

### 6-5. 安全表示

1-2 の原則③と4-2の⑤⑥のとおり。「要確認」「注意」「必ずリーダーに確認」「見当たりません」「AIの翻訳です」「下書きです」「目安」は、元より目立たなくしない・隠さない・遅らせない。AIに書かせず、プログラムが言語ごとの決まった文で出すもの（design-v0.3 2-2）は、そのまま。

### 6-6. コードの書き方

コメントは日本語で「なぜ」を書く。フレームワークとビルドを入れない。画面の CSS は `/css/<画面>.css` に置き、トークンだけを使う。
