# 実演の台本（デモ1・2）

設計書 v0.2 の「9. 実演の台本」に沿った進行メモ。各3分。**「◯時間削減できます」とは言わない。** 言うなら「月5万円の元を取る目安は、事務の作業なら月33時間、社長の時間なら月10時間。実際の数字はお試しで測ります」。

## 事前準備
- スマホとPCで `https://demo.withsoegi.jp` を開き、合言葉を入れておく
- レシート：架空のレシート、または本人の私物を10枚。**手書きの領収書を1〜2枚**混ぜる。わざと「合計と内訳が合わないもの」「インボイス番号の無いもの」「同じレシートの2枚目」を1枚ずつ入れておくと、黄・赤・重複が見せられる
- 勤怠：サンプルCSV（`/sample/attendance-sample-2026-09.csv`）。ダウンロード済みにしておくと、通信が悪い場所でも「CSVを選ぶ」で見せられる

## ① 経理：レシート → Excel（税理士・事務を兼ねる社長向け）
| 時間 | 話すこと | 操作 |
|---|---|---|
| 0:00 | 「顧問先からのレシートの入力に、何時間かかっていますか」 | （答えを聞く） |
| 0:30 | 「撮るだけです」 | 10枚を撮る／選ぶ → 読み取る（進み具合が出る） |
| 1:15 | 「AIは読むだけ。チェックは仕組み、最後は人です」 | 黄（自信がない）・赤（内訳が合わない／登録番号がおかしい）・「重複の疑い」を見せ、その場で1か所直す。科目は「候補」であることを言う |
| 2:00 | 「事務所の様式に合わせて出せます」 | 「仕訳の形」を選んでExcelを出して開く（標準様式も一瞬見せる） |
| 2:40 | 「事務所の様式に合わせるのが、お試し導入（1ヶ月5万円）です」 | 料金の一文を見せる |

注意：電子帳簿保存法のスキャナ保存の要件を満たす仕組みではない。原本の保存は今までどおり。

## ② 労務：打刻データ → 残業の集計（社長向け）
| 時間 | 話すこと | 操作 |
|---|---|---|
| 0:00 | 「残業が一番多い人、すぐ分かりますか」 | （答えを聞く） |
| 0:20 | 「打刻のCSVを入れるだけです。ここはAIを使わず、計算はプログラムです」 | 「サンプルを使う」→ 計算する |
| 1:00 | 「橙の人がいます。80時間に近いのが、月末ではなく途中で分かります」 | 青木さんの横棒（橙・6連勤）を押して日別表を見せる。伊藤さん（黄）、遠藤さん（深夜・日またぎ・休日出勤）も一言 |
| 2:00 | 「月末の手計算が要らなくなり、月の途中で気づけます」 | Excelを出して開く（一覧／1人1シート／使った設定） |
| 2:40 | お試し導入の話。上限は目安で、判断は社労士へ、と添える | 料金の一文 |

補足：週40時間超は参考表示のみ。法定休日・締め日・休憩の既定は設定で変えられる（Excelの「使った設定」シートにも残る）。写真（タイムカード）は副の入力で、必ず確認画面で直してから計算する。

## 聞かれそうなこと
- **データはどこに残る？** 何も保存しません。画像・入力・結果はサーバーに残さず、ログにも本文を出しません。読み取りだけ外部のAIサービスを使います（デモは DeepSeek。お客さんのデータを扱う導入は Claude に切り替えます）
- **正確さは？** 読み取りは完璧ではないので、色と指摘で人が見る箇所を絞ります。残業の計算は読み取りではなく、プログラムです
