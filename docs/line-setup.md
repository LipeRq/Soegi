# LINE で答えるデモ：オーナーの設定手順

コードは `src/demos/line.js`（Worker の `POST /line/webhook`）に入っています。**LINE の公式アカウントを作るのも、鍵を入れるのも、オーナーの作業**です。LINE の管理画面の名前や手順は変わることがあるので、画面の表示に合わせてください（ここに書いたのは、2026年10月時点の設計上の手順です。**実際の管理画面で確かめていません**）。

## 1. 作るもの

| 項目 | 内容 |
|---|---|
| アカウント | デモ用の**架空の** LINE 公式アカウント（名前は「ソエギ デモ」など）。プランは**コミュニケーションプラン（無料）**でよい。返信は「応答メッセージ（reply）」だけを使うので、**送信の通数には数えられない**（LINE の公式の説明で確かめてください） |
| チャネル | LINE Developers で「Messaging API」のチャネルを作る（プロバイダーを1つ作る → チャネルを作る） |
| 秘密の値 | チャネルシークレット（チャネルの基本設定）、チャネルアクセストークン（長期。Messaging API 設定で発行） |

## 2. Worker に鍵を入れる

```
wrangler secret put LINE_CHANNEL_SECRET
wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
```

ローカルで試すときは `.dev.vars` に `LINE_CHANNEL_SECRET=…` と `LINE_CHANNEL_ACCESS_TOKEN=…` を書く（`.dev.vars` は git に入れない）。**鍵はチャットやコードに貼らない**。

## 2-2. KV を作る（LINE で答えるときは必須）

モードの記憶（24時間）・1日20回・通知の重複の除外は KV に置きます。KV が無いと Worker のメモリだけになり、**インスタンスをまたいで共有されないので、モードが戻ったり、回数の制限が効かなかったりします**（あいさつの「24時間覚えます」も事実と合わなくなります）。

```
npx wrangler kv namespace create DEMO_KV
```

表示された `id` を `wrangler.toml` の `[[kv_namespaces]]`（コメントアウトされている所）に入れて、コメントを外し、デプロイします。KV は結果整合なので、回数の上限は「目安」です（同時にたくさん送られると、少し超えることがあります）。

## 3. LINE 側の設定

1. Messaging API 設定の「Webhook URL」に `https://demo.withsoegi.jp/line/webhook` を入れて、「検証」を押す（成功すれば、署名の確認と 200 の返事が動いている）。
2. 「Webhook の利用」を**オン**。
3. LINE Official Account Manager の「応答設定」で、**応答メッセージ（自動返信）をオフ**、**あいさつメッセージをオフ**（あいさつは、このデモが自分で出す。両方オンだと二重に出る）。
4. **グループトークへの参加を許可しない**（このデモはグループでは答えない）。
5. Webhook の**再送はオフ**のままにする（オンでも、同じ通知は10分のあいだ1回だけ処理します）。

## 4. 確かめること（オーナーのスマホで）

| 操作 | 期待 |
|---|---|
| QR（または ID）で友だち追加 | 「ソエギのデモです。入力した文章は保存しません。答えは外部のAI（…）が作ります。名前や電話番号は送らないでください。モードの選択だけ24時間覚えます」＋札「宿のデモ」「ソエギの案内」 |
| 「料金はいくら？」 | ソエギのサイトの内容だけで答える。リンクは `https://withsoegi.jp/…` だけ（`#` だけのものは出ない） |
| 札「宿のデモ」→ 「Do you have a pick-up service?」 | 英語の返信の下書き＋「【デモ】これは、宿のスタッフが確認してから送る『下書き』です。」＋確かめる点 |
| スタンプ・写真を送る | 「文字でお送りください」 |
| 301文字以上 | 「質問は300文字までにしてください」 |
| 21回目（同じ日） | 「本日の質問は20回までです」 |
| 友だちをブロックして、また追加 | もう一度あいさつが出る |

## 5. 仕様の覚え書き

- **署名**：受け取った本文を、**バイト列のまま**（文字にする前に）、チャネルシークレットで HMAC-SHA256 → base64 にして、`x-line-signature` と定数時間で比べる。違えば 401。LINE の管理画面の「検証」は、イベントが空でも 200 を返す。
- **返し方**：署名を確かめたらすぐ 200 を返し、AI への問い合わせと返信は `ctx.waitUntil` で後から行う。AI の待ちは25秒で打ち切り、「うまく答えられませんでした」を返す（応答トークンは1回だけ・約1分で切れる）。
- **保存するもの**：モード（宿／ソエギ）だけ。LINE の利用者IDは、そのまま残さずハッシュにして、KV（`DEMO_KV`）に24時間だけ置く。無ければ Worker のメモリ（ローカル開発用）。質問の本文はログにも出さない。
- **回数**：1人1日20回（ハッシュにした利用者IDで数える）。切り替え・文字以外・長すぎる質問は数えない（切り替えは別に1日100回まで）。アカウント全体で1日1,000回まで（費用の歯止め。Turnstile の無い LINE は、これが上限）。同じ通知（`webhookEventId`）は10分のあいだ1回だけ処理し、10分より古い通知は捨てる。イベントは1リクエストに5件まで、順に処理する。
- **グループ・ルーム**：答えない。**文字以外**：「文字でお送りください」。
- **AI**：宿のモードは宿の問い合わせの下書き（`draft`）、ソエギのモードはサイトのチャットボット（`answerSite`、プロフィール `soegi`）と同じ。
- **見せ方（残り）**：QR は LINE の管理画面から作る。宿・チャットボットの画面と持ち帰り1枚に載せるかは、アカウントができてから決める。
